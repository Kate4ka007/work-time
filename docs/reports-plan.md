# Отчёты: вчера и все проекты

Технический план. Два слайса, четыре файла. Контракт отчёта по одному проекту не меняется.

Риск низкий. Страница `/reports`, без API и без смены схемы. Данные уже в Pinia, `buildReport` считает отчёт на клиенте.

## Допущения

- «Вчера» — четвёртый пресет рядом с «День», «Неделя», «Месяц». Ставит обе даты на вчера. «День» по-прежнему сегодня.
- «Все проекты» — пункт в текущем селекте. Дефолт остаётся первый проект.
- В режиме «все» на экране итог, доли по проектам и список задач за тот же период. Чекбоксы исключения задач работают как сейчас.
- «Вчера всё время» — оба фильтра вместе.

## Что уже есть

- `PeriodSelector` и `periodToDateStrings` / `getPeriodRange` в `shared/utils/reports.ts`. Периоды: `day | week | month`.
- `buildReport` всегда фильтрует один `projectId` и отдаёт одну строку на 100%.
- `ReportSummary` уже рисует несколько строк проекта с длительностью и процентом.
- `ReportTaskList` уже имеет неиспользуемый стиль `.task-list__project`.
- Пустые состояния страницы уже есть: нет проектов, нет данных за период, нет задач.

Новых абстракций нет. `ReportSummary.vue`, стор и API не трогать.

## Контракт

В `shared/utils/reports.ts`:

```ts
export const ALL_PROJECTS_ID = 'all'
export type ReportPeriod = 'day' | 'yesterday' | 'week' | 'month'
```

`projectId` остаётся `string`. Страница передаёт UUID или `ALL_PROJECTS_ID`. Пустая строка по-прежнему значит «проект ещё не выбран».

Id проектов — UUID (`server/utils/store.ts`, `generateId`). Строка `all` с ними не совпадает.

`ReportResult` не меняется.

## Слайс 1. `shared/utils/reports.ts`

### Вчера

В `getPeriodRange` ветка `yesterday`:

```ts
const day = subDays(referenceDate, 1)
return { start: startOfDay(day), end: endOfDay(day) }
```

`periodToDateStrings` подхватит сам. `getTodayTotalMs` остаётся на `'day'`.

### Охват задач

- `ALL_PROJECTS_ID` — все `store.tasks`.
- Иначе — `task.projectId === projectId`, как сейчас.

Дальше тот же пайплайн: записи с `startedAt` внутри `[start, end]` (`isWithinInterval`, границы включительно), задача в охвате.

Активный таймер в `entries` не входит. Запись через полночь считается в день `startedAt`.

### Две суммы

Поведение текущее, один код на оба режима.

- `fullDurationByTask` — все записи охвата. Это длительность в списке задач.
- `durationByTask` и `totalMs` — без `excludedTaskIds`. Это итог, доли проектов и `percentage` задачи.

Исключённая задача остаётся в списке со своей полной длительностью и `percentage: 0`. Если исключены все, `totalMs === 0`, `rows` пустые, задачи на экране остаются.

### Строки проектов

Один путь для обоих режимов. По включённым записям суммировать `durationMs` в `Map<projectId, number>`. Строка только если сумма больше нуля:

```ts
percentage = totalMs > 0 ? durationMs / totalMs * 100 : 0
```

Сортировка по `durationMs` по убыванию. Для одного проекта доля выходит 100. Задача без проекта в сторе пропускается.

### Задачи

Текущая формула. В режиме «все» в охват входят задачи всех проектов, у каждой строки уже есть `project`.

## Слайс 2. UI

### `app/components/PeriodSelector.vue`

Четвёртая кнопка. Порядок: День, Вчера, Неделя, Месяц. Значение `yesterday`. Разметка кнопок та же.

### `app/pages/reports.vue`

- Подзаголовок: `Сводка по времени`.
- В селект первой опцией `<option value="all">Все проекты</option>`. Импорт `ALL_PROJECTS_ID`.
- Вотчер проектов: пустой id по-прежнему ставит первый проект. Сброс на первый проект только если id не `all` и его нет среди проектов. Выбранное «все» при удалении одного проекта сохраняется.
- `buildReport` вызывать и для `all`. Пустой отчёт только пока `selectedProjectId === ''`.
- Шапка с цветом и именем (`v-if="selectedProject"`) для `all` сама скрывается: проект не находится.
- `ReportTaskList` получает `show-project`, истина только при `all`.
- Сброс `excludedTaskIds` при смене дат и проекта уже есть. Смена на «все» и на «вчера» сбрасывает галочки тем же вотчером.

### `app/components/ReportTaskList.vue`

Проп `showProject?: boolean`. Под именем задачи:

```vue
<span v-if="showProject" class="task-list__project">{{ row.project.name }}</span>
```

Класс уже есть, элемент добавить.

## Готово, когда

Один проект, неделя, исключение задачи: итог, одна строка на 100%, задача в списке с полной длительностью. Совпадает с текущим экраном.

Вчера ставит обе даты на вчерашний календарный день. Все проекты дают итог и строки с долями, сумма долей 100. Вчера и все проекты вместе. Пустой период показывает уже существующие пустые тексты. Нет проектов — прежний empty state и ссылка на `/projects`.

Проверка: `npm run build`, затем в браузере эти четыре прохода. Отдельного тест-раннера в `package.json` нет, фреймворк не добавлять.

## Вне слайса

- Подсветка пресета не гаснет, если после него править даты руками. Так уже работает у «Недели».
- Округление `toFixed(0)` может дать 99 или 101 на нескольких проектах.
